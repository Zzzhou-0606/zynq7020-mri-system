# 接入配置与数据契约

先填写接口审核表，未知项写“待确认”及取证方式。核对完成后，将实际参数填入Notebook或master契约配置。

| 字段 | 填写内容 | 从哪里核对 | 缺失时的处理 |
|---|---|---|---|
| 板卡 | 厂商、完整型号、硬件版本、FPGA part | 丝印、原理图、工程 part | 不下载其他板卡位流 |
| 软件环境 | 镜像、PYNQ/Python 版本、内核、访问地址 | environment、系统启动信息 | 先解决板端内核选择 |
| 硬件文件 | bit/hwh 文件及同次构建记录 | Vivado 导出目录、构建清单 | 重取配套文件 |
| 数据接口 | AXI Stream＋DMA 或 m_axi | Block Design、HLS 接口 | 不混用两个运行器 |
| IP 名称与范围 | 完整层级名称、VLNV、地址范围 | overlay.ip_dict、HWH | 不猜地址 |
| 控制协议 | ap_ctrl_none / ap_ctrl_hs / 其他 | HLS 头文件、RTL接口 | 其他协议单独适配 |
| DMA 参数 | simple/SG、双通道、Micro、长度位宽、数据位宽 | HWH parameters | 自动 DMA 运行器要求完整元数据 |
| 输入 | 名称、shape、dtype、布局、字节序、字节数 | 模型/算子接口规范 | 先写软件参考 |
| 输出 | shape、dtype、字节数、语义 | 独立参考实现 | 不按收到多少就比较多少 |
| 流结束 | TLAST 对应帧尾，TKEEP 对应有效字节 | RTL/HLS与连接图 | 未明确前不启动流测试 |
| master 指针 | 每个缓冲区的偏移、32/64位、读写方向 | 生成的驱动头文件和 HWH | 不从邻近寄存器推测 |
| 标量 | 长度单位、偏移、值、符号编码 | 驱动头文件、算法定义 | 明确 N 是元素数还是字节数 |
| 内存 | PYNQ allocate 或设备树预留区、缓存同步、地址可达性 | 系统配置和硬件互联 | 不能把虚拟地址给 PL |
| 数值判据 | 整数精确相等；浮点预定 atol/rtol | 算法误差/量化规范 | 不为通过临时放宽 |
| 超时与恢复 | 超时秒数、谁独占硬件、如何确认停机 | 测试计划、复位设计 | 未确认停止不释放缓冲区 |

## 三个容易混淆的单位

- `uint32` 的 N 个元素是 `4*N` 字节；DMA 长度寄存器计字节。14 位长度字段上限是 16383 字节，4096 个 uint32 已经超限。
- `device_address` 是设备可用地址，普通 NumPy 对象的内存地址不能替代它。
- 64 位指针寄存器通常分低/高两个32位字；只有头文件明确这一布局时才使用适配器的连续两字写法。

## 从回环改成算法

回环使用 `expected=x.copy()`。换成算法时，一起更新输入生成、独立参考、输出规格和回归样本，并替换Notebook最后的回环测试单元。参见 [仿射案例](../examples/affine_u32/README.md)。

多输入、多输出、原地更新可以用 master 的多个命名缓冲区；DMA 运行器仍只有一入一出，不做多流调度。任何硬件协议变更都需要同步修改契约和验收记录。
